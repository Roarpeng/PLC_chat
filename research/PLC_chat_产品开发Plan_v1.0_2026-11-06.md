## 1. 计划定位与边界

### 1.1 本计划解决的问题

基线报告已定义「做什么」（产品定义、1:1 契约、目标架构、F1–F20 文件级改造、P0/P1/P2 路线图）。本计划只回答四件事：**按什么顺序做、凭什么判定完成、卡住了怎么办、什么不做**。

产品定位已由基线报告 §13.1 改写：从「一次性生成器」升级为「**持续迭代的工程伴生工具**」。因此 Action C 不是附加功能，而是主链组成部分；P0-G 是整条增量链的真机地基与关键路径起点。

### 1.2 范围

| 包含 | 不包含 |
|---|---|
| WP-00～WP-10 的设计、实现、单测、真机验收、证据归档、文档同步 | 本轮改动 `plc_project/` 下任何产品代码（需另行拍板「实施准入」） |

| 风险登记、变更管理、RTM 追溯 | P2-C MCP 化（可选，Could） |

### 1.3 状态词（全文统一）

| 词 | 含义 |
|---|---|
| **必须** | 强制要求，未满足即判定不通过 |

| **可以** | 可选，不构成验收条件 |

## 2. 目标与 Definition of Done

### 2.1 产品目标

主链：新建项目（逻辑占位拓扑）→ 项目内对话（`project_id`）→ Canvas 业务语言编辑 → 硬门禁确认冻结 vN → **Action A 导出工程包／Action B 首次写入博途／Action C 调试期增量回写** → 调试期在同一份已打开工程上反复增量修改，不重载项目。

### 2.2 四层验收（Definition of Done）

| 层 | 判定 | 证据产物 | 归属闸门 |
|---|---|---|---|
| **L1 逻辑等价** | `fidelity_ok`：`coverage == 1.0` ∧ `orphan == 0` ∧ `drift == 0` ∧ `tia_side_drift == 0` | `fidelity_report.json`（含 `coverage_matrix`／`orphan_blocks`／`drift_items`／`ob_number_deviations`） | G2、G3 |
| **L2 可编译** | `compile_error == 0` ∧ 四层静态门禁通过；warning 单列**不并入成功**；`tia_unavailable` 显式失败 | 结构化编译报告（error 数／warning 清单／块清单／耗时／TIA 版本／路径） | G1 |
| **L3 可复现** | 同 `spec_hash` 两次生成产物哈希一致；服务重启可从 `specs/vN.json` 恢复 FROZEN vN | `reproducibility` 记录 + `.zap19` + 重启恢复记录 | G2 |
| **L4 增量可迭代** | 同一会话连续 ≥3 次增量回写，每次 `fidelity_ok` 且 `error_count == 0` 且 `tia_side_drift == 0`；项目未关闭／未重载／未新建 | 增量 `fidelity_report` + PCEC 账本 3 条 + 会话句柄复用记录 | G1（地基）→ G3（完整） |

> **最终验收 = `L1 ∧ L2 ∧ L3 ∧ L4`**，四者缺一**禁止**宣称「1:1 完成」（基线报告 §13.9）。

### 2.3 闸门与验收层绑定

| 闸门 | 绑定层 | 判定性质 |
|---|---|---|
| G0 准入 | 无（前置决策） | 技术路线与环境 go/no-go |
| G1 地基 | L2 正式通过；L4 的**真机地基**（P0-G 三次增量，尚无增量 fidelity 报告） | 编译判定与会话可用性 |
| G2 等价 | L1 部分通过；L3 正式通过；L4 的**反向保护与增量报告** | 差异／保护／持久化／增量校验 |
| G3 迭代 | L1 正式通过；**L4 完整通过** | 三动作齐备 + §13.9 六条用例 |
| M4 发布门禁 | `L1 ∧ L2 ∧ L3 ∧ L4` 全绿 + 证据包归档 | 交付判定 |

> G1 的 P0-G 验收**不等于** L4 通过：P0-G 只验「不重载 + 编译零错误 + PCEC 三条」，完整 L4 还需 §13.9 的 `fidelity_ok` 与 `tia_side_drift == 0`（基线报告 §13.8）。
