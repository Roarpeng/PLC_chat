### 6.2 诊断性变体（定位第二根因，非改产品代码）

| 文件 | 真实失败 |
|---|---|
| `cases/uc04_diag2a/import.json`（仅 `zh-CN`） | `"The namespace 'http://www.siemens.com/automation/Openness/SW/NetworkSource/StructuredText/v4' is incorrect."` |
| `cases/uc04_diag2b/import.json`（无 MultilingualText） | 同上 `StructuredText/v4` namespace 错误 |

对照真实 V19 导出先例 `PLC_Openness_data/hr001/export/plc/CPU_1200/blocks/OB1Main.xml:83`：`<FlgNet xmlns=".../SW/NetworkSource/FlgNet/v5">`（LAD 用 FlgNet），而自产模板 `_render_ob_xml` 用 `<StructuredText xmlns=".../StructuredText/v4">`。**最小改动真实先例（仅 Name/Number/culture）即可导入成功**（§5.4），反证缺陷在自产模板本身。

### 6.3 过程性失败（如实记录，非主结论）

| 文件 | 失败 | 原因 |
|---|---|---|
| `cases/uc04_diag/export_block.json` | `inconsistent_blocks`: `Block 'Main' IsConsistent=false ... Compile the PLC software in TIA Portal, then retry.` | one-shot 独立会话不保留编译态 |
| `cases/uc04_diag/import_variant.json` | `not_found`: `XML file not found: ...OB123_zhCN_variant.xml` | python 收到 `/c/...` 路径未转换，变体未生成（后改用 `C:/...` 修正） |
| `cases/uc01_obnum/import.json` / `uc01_swunit/import.json` | `A rung must have at least two connections at the object with UID '23'.` | 自行构造的空 FlgNet 网络不满足 LAD rung 约束（构造问题，非自产 XML 问题） |

### 6.4 结论

- 自产 `xml_supplement/ob/*.xml` 在 V19 导入失败：`openness_error`（culture `en-US` 不匹配 + `StructuredText/v4` namespace 不正确）。
- `xml_supplement/folders.json` 是**文档化清单**（`tia_delivery.py:63-67` `_FOLDER_NOTE`），非 `import-xml` 的 SimaticML 对象，不能「直接导入成功」；其分组可经 `create-block-group` 建立（§5.3），但 `SW.PlcBlockGroup XML` 可导入性仍未确证。
- **`xml_package_unverified` 不可消除，保持 `True`**；UC-04 标 `pending_real_machine`（K1 待 Agent G 修复模板后复测）。**未改 `tia_delivery.py`**。
