00 / Executive decisions

先拍板五个技术原则

以下是建议实施的默认方案；与已确定的 AF Basic 文件夹版路线保持一致。

01

同一个工程工作区

新项目和旧项目都进入 ProjectWorkspace。只在初始化策略和变更约束上分叉。

02

一个权威语义模型

自然语言、设备 Canvas、步序 Canvas 都操作同一 EngineeringIR；图形不是另一个数据库。

03

驱动和工艺分离

DriverSpec 控制元件的行为；SequenceIR 决定什么时间调用它。

04

AI 只提交候选变更

LLM 不返回直接执行的 SCL；必须先生成受限 Patch，经过规则验证和人工批准。

05

TIA 是工程事实来源

可下载源码包 ≠ 完整工程。只有实际编译、保存、归档并核对的 .zap19 才是原生交付。

→

第一里程碑

双作用气缸案例：自然语言建驱动→图上修改步序→TIA 编译归档→重新导入并修改。

重构战略： 不推倒现有代码。把 Greenfield 现有的 GreenfieldIR + AF Generator + PCEC + Openness 抽象成共享内核，旧项目先通过 Adapter 接入。禁止拷贝一套新的后端重新发明相同功能。

02 / Scope and compatibility

明确范围：AF 版本与硬件占位

AF 不切换用户已选择的档位

当前目标： TIA V19 + AF Basic 普通 BlockGroup 文件夹结构，Unit / EM / CM 层级和状态语义。仓库已有 AF_PROFILE=SIEMENS_AF_BASIC_FOLDER_V19 与 AF V1.2 Generator。保留现有基线；不擅自切换到真正的 Software Unit。新增 af_profile_id + library_version + template_sha256，不得把 Siemens AF V1.2、AF Basic V2.2、AF V3.0 的文档与库接口默认为同一版本。

“真实工程”与“占位”要分层

真实： 调用 TIA Openness 创建 .ap19；若要生成可编译逻辑，使用已确认、受支持的 CPU 设备或预制 CPU 骨架。
占位： 元器件、接线、I/O 标签地址、站内通讯和设备参数可以保留 unbound；不自动编造 %I/%Q 地址。
不能混淆： 只有空 TIA Project 而无 PlcSoftware 时，不能声称 PLC 编译完成。

功能级别当前版本必须支持明确不做 / 需要独立审批
硬件组态真实工程 / CPU 骨架 + 逻辑占位 + TIA 导出树自动规划全部网络/从站/GSD/IO-Link 物理组态
软件CM、EM、步序、联锁、变量/UDT、OB 调用、编译未经确认自动在线下载、修改 F-block 或解锁受保护程序
旧工程只读解析、明确可写范围内的增删改、复制验证默认强制 AF 改造整个旧项目；静默重排 DB 偏移/硬件地址
安全外部安全许可反馈、软件行为约束、事件记录把普通 SCL 联锁误作安全完整性的急停功能
安全边界：急停、光幕等安全功能必须由合适的安全控制系统、风险评估与验证承担。本产品可表达“安全许可丢失时普通工艺禁止新动作”的软件接口，但不默认生成安全完整性等级相关的 F 程序。

关键建模决定

  • 对象 ID 与名称分离：cm_clamp 是不可变 ID，cylClamp 是可改展示/生成名。修改名字不能导致已有引用失效。
  • IR 与 TIA 块不是一一对应：一个 EM 的步序可能派生 FB、实例 DB、OB 等多个块。SourceMap 必须支持 N:N。
  • 强类型 Guard AST：不能在生成器里接受 eval()、拼接任意自然语言作为 SCL 布尔表达式。
  • 图形布局不进入工程语义哈希：步骤位置、缩放、颜色属于 UI layout；改变这些不应导致 SCL 重新生成。
  • 明确未绑定：物理地址 null 和“假默认地址 %Q0.0”含义完全不同；源代码生成不能偷偷使用占位符地址。
06 / Agent orchestration

Agent 是编排层，编译/校验必须可重复

Coordinator / Intent Router

分类任务：问答、增加元器件、调整驱动、变更工艺、查询旧工程、生成预览、执行工程交付。调用只读检索和候选变更工具。

Component Engineer

自然语言 → 组件类型与参数 → 标准 DriverSpec → CM 实例。未知端口不得自行补出物理地址。

Process Engineer

自然语言 → 步骤、动作、转移、联锁、异常 → SequenceIR。不能提交未经校验的自由文本代码。

Project Analyst

旧工程块检索、引用关系、现状解释、修改目标定位、受影响范围分析，遇到不确定来源标注。

Review Planner

对候选 Patch 生成影响分析、测试场景、风险等级和用户需要补充的决策。

TIA Executor / deterministic

不是放权给 LLM 的自由 Agent。它是受控事务服务：准备→编译→保存→归档；所有写操作由显式批准触发。

07 / Core algorithms

核心算法设计：从语言到可编译控制程序

以下是重构最重要的算法合同，算法应独立于 React 和 TIA Openness，具备纯函数单元测试。

A1 · 自然语言 → 类型化需求 → CandidatePatch

function parse_request(message, context):
  intent = llm.extract(message, schema=IntentSchema)
  targets = resolver.match(intent.targets, context.symbol_index)
  if ambiguous(targets) or missing_required(intent):
      return ClarificationIssues(unresolved_slots, candidate_ids)
  proposal = domain_mapper.to_patch(intent, targets)
  preview = apply_to_clone(current_ir, proposal)
  errors = validate_all(preview)
  if errors: return RejectedProposal(errors, unchanged_ir_hash)
  return CandidatePatch(ops=proposal, before_hash, after_hash, explanation)

# LLM never returns unrestricted SCL for direct TIA execution.

实现重点：规则表先识别“气缸/电机/按钮/开关”等常见实体，再使用 LLM 结构化填槽；别名词典解决“夹紧气缸/气缸1/cylClamp”指代；字段来源分别标记 user_explicit / inferred / imported / library_default。未知关键参数在确认前进入问题队列。

A2 · 元器件 Driver 自动合成

阶段确定性算法输出
分类设备类型 → CM Catalog 匹配；无法命中则标 custom_pendingcomponent_type / template_id
接口从模板抽取命令/反馈/参数，生成 typed ports；区分必需/可选DriverSpec
行为把状态转移表编译为故障/超时/动作状态机；避免同时驱动反向线圈Driver FSM
AF 绑定生成 CM 控制节点、实例、Config、CallEquipment 引用，优先官方 LBC 模板AF CM + SCL/XML
安全检查端口类型校验、单写点、命令冲突、异常路径、无绑定 IO 明示DriverValidation

驱动内核例：IDLE → EXTENDING → EXTENDED → RETRACTING → RETRACTED，另有 FAULT；命令在自动和手动模式下通过唯一仲裁器进入驱动，并不能绕过 SafetyPermit。对于不确定的阀型、失电状态和恢复策略，必须要求工程师确认。

A3 · 步序图的有限状态语义（SFC-like）

第一版建议使用受限 SFC 语义，生成 SCL 中的确定性步进状态机；不要声称生成与 TIA GRAPH 完全等价的原生 GRAPH 工程。

SequenceIR = (Steps, Transitions, Actions, Guards, Modes, Exceptions)
Step = {id, entry_actions[], cyclic_actions[], exit_actions[],
        min_duration, max_duration, failure_target}
Transition = {from[], to[], guard_ast, priority, edge_type}

# 在“当前扫描周期开始时”的稳定快照上判定转换：
scan(input_snapshot, active_steps, timers, driver_feedback):
  snapshot = freeze(input_snapshot, active_steps, driver_feedback)
  enabled = evaluate_typed_guards(snapshot)                # no eval()
  selected = resolve_priority_and_fork_join(enabled)       # deterministic
  next_steps = atomic_transition(active_steps, selected)
  actions = compose_actions(next_steps)                    # documented policy
  commands = arbitrate_single_writer(actions, safety_permit)
  next_drivers = tick_driver_fsms(commands, snapshot, timers)
  return next_steps, next_drivers, trace

# Scan ordering is fixed and documented; compiled SCL and simulator must match.

若以后支持真正的并行 Step，需要引入 Token/Fork/Join 语义，避免用一个整数 CASE step 假装可处理并行分支。默认 MVP 先实现确定性串行步骤、优先级分支和异常路径；并行图可以展示但在实现其运行语义前必须阻止交付。

A4 · 自动验证：图论 + 类型系统 + 约束求解

图论

DFS/BFS 判定不可达步骤与未到达终态；Tarjan SCC 检查非终止循环；DAG/拓扑排序处理生成块依赖；反向调用索引分析删除后影响。

类型与资源检查

Guard AST 中 BOOL/TIME/INT 等类型统一；命令端口与反馈端口不能混用；对所有物理输出及符号映射做单写者和互斥约束。

互斥和死锁

同一步两个分支的 Guard 若同时成立，必须有显式 priority，或采用约束求解检查互斥。不能用输入顺序偷偷决定执行顺序。

故障场景

每个运动/执行步骤自动产生超时、反馈不一致、SafetyPermit 失效、复位重新进入等测试场景；出错时返回最短反例路径。

def validate_process(ir):
    errors = []
    errors += schema_and_type_checks(ir)
    errors += unknown_reference_checks(ir)
    errors += graph_reachability(ir.steps, ir.initial_step)
    errors += scc_without_exit_checks(ir.transitions)
    errors += branch_priority_or_exclusivity_checks(ir.transitions)
    errors += single_writer_checks(ir.io_bindings, ir.drivers, ir.steps)
    errors += driver_precondition_checks(ir)
    errors += cycle_and_timeout_policy_checks(ir)
    errors += unsupported_parallel_construct_checks(ir)

A5 · 带 Trace 的离线运行器：可预测，不冒充实机

使用 Scenario = [(t, input_signal, value), …] 定义外部输入波形；用与 SCL Lowering 共享的语义规则逐个扫描周期更新状态。记录 TraceFrame：周期、活动步骤、条件、动作、Driver 状态、输出、报警、SourceMap。时序图仅渲染 Trace；若测试结果来自 TIA PLCSIM 或真实 PLC，必须显式显示 data_source。

A6 · IR → SCL / SimaticML 编译（最关键的确定性层）

FrozenSpec + AFProfile
    → semantic validation (not just Mermaid parsing)
    → typed lowering to AF roles / UDT / FB / DB / FC / OB
    → symbol table & number allocator (respect imported block registry)
    → dependency graph: UDT → FB / FC → instance DB → call OB
    → emit SCL / SimaticML with source_id annotations + SourceMap
    → SCL syntax precheck + AF linter + single_writer checks
    → ArtifactManifest {files, sha256, import_order, dependencies}

# Avoid generating block names by regex on DB suffix when explicit source IDs exist.
# Never invent block numbers, do not assume DB / FB are one-to-one.

产物确定性测试：同一冻结 IR + AFProfile + 模板 hash，重复编译两次应得到相同的语义文件及 manifest hash（可变时间戳移到独立 receipt）。编译错误映射：TIA block/file/line → SourceMap → IR 节点 → Canvas 红色标记。

A7 · 新增/修改/删除的最小变更规划

Openness Worker 职责与线程模型

  • Windows 专属：C# Siemens.Engineering API；新建项目使用 Projects.Create，创建 CPU 使用已在本机证明支持的 Devices.CreateWithItem。
  • 每项目独占：一个写入事务、一条 STA 执行队列；禁止两个 Agent 并发打开同一工作副本并同时写入。
  • 实际创建路径：C# create-project 返回 {ok, create:{projectPath}}，Python 必须解包此字段并失败关闭，不允许猜测路径。
  • 明确准备副本：旧工程首先 Openness Retrieve/copy 成独立路径，验证快照后写入副本。
  • 可恢复性：作业阶段写持久 ledger；如果进程中断，恢复时检测现存工程和实际成果，不盲目重发非幂等写入。
  • 交付校验：CompilerResult 的 State/ErrorCount/WarningCount，Save 后 Archive 返回路径，计算 hash，必要时在独立目标目录 Retrieve + reopen（增强验收）。

09 / Brownfield change engineering

旧 TIA 工程：先保真，再实现最小增删改

导入分层

层 A：原生项目快照、设备树、硬件版本、原始字节。
层 B：可解析块、标签、引用图、接口与编号。
层 C：AF 角色分析和用户工艺语义。
不可解析区域必须保留原文/原件及其属性，不能悄悄消失。

变更策略

默认：只修改明确选择的目标块与必要依赖。
增加：先检查编号/符号冲突。
删除：反向引用闭包检查，含实例 DB、OB、调用边。
重构 AF：单独的高风险明确任务，不是编辑旧工程的前置条件。

导入建立 SourceBinding

保真验证：未修改的原始块应在导出后以适合该对象的语义/字节级比较策略校验。不能要求所有 TIA 导出 XML 原样字节相同（导出顺序/元数据可能变化）；对 PLC 块源、接口、布局、属性、硬件和 F 块分别选择可验证的比较方法，并保存异常说明。

最小修改的“四次闸门”

G1

编辑许可

目标块可写；无受保护/F-block 内容；用户目标明确。

G2

Diff 审核

新增/修改/删除明确列出；依赖和地址不冲突。

G3

基线未漂移

写前再次确认原工程/副本版本与批准时一致。

G4

编译 + 保真

新副本编译成功；不受影响区域未出现意外变更。

当新的自然语言指令涉及既有 LAD/GRAPH 逻辑且无法证明正确的源码转换时，应提出候选修改与人工操作说明，而不是虚构完整自动回写能力。

  • 同时维护 GreenfieldIR、CanvasState、ProjectIR 三份都允许任意写入的模型。
  • 大范围修改 40+ 旧接口但不保持行为回归，随后依赖 LLM 修复编译错误。
  • 让 React 前端保存完整工程真值、后端只存一次 session；刷新或服务重启造成“工程消失”。
  • 把一个 Python/C# 服务中的每个函数包装成 Agent，导致权限边界难以审计。
12 / Acceptance and industrial safety

质量与可验证性：定义硬闸门

Gate验收要求测试方式
G0 / 契约确定版本、TiaCapabilityManifest、CPU 模板和 AFProfileSchema + Windows status 实机探针
G1 / IR同一 IR 可以完整序列化、Patch 原子性、Canvas 投影不反向覆写pytest pure functions + vitest
G2 / 驱动所有必需端口、超时、反向互斥、单写者通过属性测试 + 正反例单测
G3 / 工艺可达性/异常转移/优先级/无未实现并行语义Guard AST + Graph algorithms + scenario trace
G4 / SCL确定性产物 + SourceMap + 依赖排序；静态检查通过golden files + compiler precheck
G5 / TIA真实 V19 工程导入、编译成功、Save、Archive、重新打开Windows TIA 单机集成测试，不是 mock
G6 / Brownfield原工程不动；只改批准对象；删除无悬空引用；其他块保真已知 V19 旧工程副本三类增删改案例
G7 / 故障恢复超时/编译失败/重复请求/worker 崩溃/基线漂移不造成错项目写入fault injection + transaction recovery

最小端到端回归套件

  1. Greenfield：真实 TIA V19 建工程，选择受支持 CPU，生成一只气缸控制驱动及正常/异常步序，编译 0 errors，Save，Archive 为真实 .zap19。
  2. 时序编辑：把 S2 保持时间由 1000 改为 2000 ms，验证 IR Patch、SCL diff、Trace 波形都准确变化。
  3. 重新导入：将刚归档的工程恢复成新工作区，解析真实块并定位源 ID。执行“缩回完成后增加计数”并仅生成目标增量。
  4. 旧工程修改：分别新增、修改、删除一个可写、无保留引用的普通块，比较未受影响对象。
  5. 负例：工程路径缺失、CPU 未选、两个线圈同时使能、删除被引用 FB、修改 F-block、版本漂移、未知 Guard、TIA 编译失败、归档缺失都拒绝出现“交付完成”。
重要：任何 Safety/F-block、在线下装、运行/停止设备的能力必须走独立风险评估、权限设计与人工授权。第一版的自动化范围仅限离线工程设计和真实 TIA 的离线编辑/编译/归档。
