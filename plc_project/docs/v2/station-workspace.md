# V2 工位工作台

打开 V2 工程后，项目画布是主界面。项目画布编排工位，双击工位节点进入设备动作画布，用顶部的项目名称返回。节点位置、连线和动作参数随草稿保存。画布、离线时序和 AF 生成共用版本化的 `station_design`。

开发范围、五阶段计划和交接验收记录见[双层画布编排开发计划](station-canvas-development-plan.md)。

## 创建或打开项目

1. 打开 `http://localhost:5173/#/v2`，选择「新建 V2 工程」。
2. 在「硬件组态」中填写 PLC CPU 和 I/O 模块，登记输入、输出信号及其地址。
3. 在项目画布从节点库拖入「新建工位」，在检查器命名。已有工位也可以拖入项目画布。双击工位节点或点击节点上的「打开工位」进入工位画布。
4. 已有项目可以用项目 ID 继续编辑。通过「导入 AF 工程」可以检查并导入 AF 画布 JSON 或包含 `af-canvas.json` 的 AF 源码 ZIP。文件须符合当前 AF Profile 和 `af-station-canvas/1` 格式，确认后会创建独立的可编辑项目。在配置了归档导入能力的环境中，单独的 `.zap19` 可检查程序块和 AF 角色，继续编辑需要配套的 AF 画布。

## 在画布上编排

从节点库拖入节点，或点击它放置在画布上。从节点右侧的「完成」「超时」「故障」等端口拉线到目标节点左侧入口。也可以点击端口旁的「＋」，选择并连上新节点。选中一条线可改接或删除。移动节点只调整布局。

项目画布的「并行分支」可以直接连接多个不同工位，各工位的完成口连到同一个「全部汇合」，故障口各自连接处理路径。工位画布的并行分支可以直接连接不同设备的预设动作，每条分支分别检查完成反馈和超时。当前并行组每条分支包含一个工位调用或动作节点。

- 工位内可搜索或按气动执行、电动执行、夹持与搬运、检测与识别、外部设备筛选。设备库包含 31 种设备，其中 16 种提供可生成 AF 的驱动。
- 拖入设备模板会创建一个实例。要让同一台设备执行另一动作，从「已有设备」拖入对应动作。选中节点即可修改动作、完成反馈、超时和 I/O 绑定。设备的默认超时可在「工位设备」中调整。
- 在画布下方输入中文，选择「预览修改」。画布会标出新增、修改或删除的节点和连线，核对后点击「应用修改」。反馈未匹配时会标记「反馈待关联」，可在检查器选择输入与期望值。生成预览会先保存已有手动草稿。
- 支持 AF 生成的伺服轴由外部定位控制器提供预置位置和数字 I/O 握手。标为「待配套驱动」的 TIA 工艺对象、总线电机、视觉或机器人等设备可先加入草稿，项目发布需要相应驱动。

以下用气动夹爪、伺服轴和光电传感器演示。设备实例名分别设为「夹爪 A」「横移伺服」「工件到位」。

> 工件到位后，夹爪 A 夹紧。夹紧到位后，横移伺服移动到工作位。伺服回原位，再松开夹爪。夹紧等待超过 2 秒就进入故障分支。

应用后可以继续输入「在松开前插入等待 300 ms」或「把夹紧的超时改为 2.5 秒」，也可在「动作步骤」中手动修改。如果已有流程需要整体重排，可用「重新生成工位流程」开头，预览时复核将被替换的步骤和连线。

项目层可以输入 `重新生成项目流程，让「工具工位 A」和「工具工位 B」并行`。要修改已有连线，可以输入 `把「节点 A」的完成出口连到「节点 B」`。

## 配置互锁

- 同一气缸的伸出与缩回由驱动内置互斥规则。并行组内如果两个动作引用同一台设备，发布检查会定位对应节点并阻止生成。
- 跨设备许可在动作的「运行许可 / 互锁」中配置。例如，在伺服的到工作位动作上选择「夹爪 A · 夹紧到位」。许可反馈以虚线显示，实线表示执行顺序。
- 「启动前检查」仅在动作开始时检查。「运行中持续检查」还会在动作执行时监测反馈，失效后撤销该动作的输出请求并走「互锁失效」出口。启动时条件未满足，可选择等待或立即走该出口。

## 类型端口与工位交接

实线表示执行路径，绿线表示类型信号，虚线表示配置的互锁关系。一个信号输入只接受一个来源，输出可以供多个目标使用。连线要求两端类型相同，环形依赖会被校验拦截。常用类型为 `BOOL`、`DINT`、`TIME`、`STRING`，气缸模式和请求分别使用 `MODE` 和 `REQUEST`。

1. 工位里拖入「信号逻辑」节点，可增加、命名和配置输入，支持 AND、OR、NOT、相等、大于和小于。将结果接到判断条件或动作启动许可。启动许可影响动作开始，持续检查仍在动作的「运行许可 / 互锁」中定义。
2. 拖入「工位接口」，定义工位公开的输入、输出及默认值。工位输入向内部节点提供信号，工位输出将内部信号发布到项目层。已连线端口允许改名称，改类型、方向或删除前需要解除相关连线。
3. 在项目画布展开工位节点的接口，连接运行许可、复位、就绪、运行中、完成、故障、报警 ID 和工位自定义端口。工件号之类的业务数据可以沿信号线传给接收工位。
4. 拖入「工位交接」并选择接收工位。节点等待接收方就绪和运行许可，发出启动请求并等接收确认。确认后使用接收方的完成与故障结果。「交接确认超时」只限制等待就绪与接收的阶段。

自然语言可以预览类型连线，例如 `把「工具工位 A」的「工件号」信号连到「交接至工具工位 B」的「接收工件号」`。

### 双作用气缸 CM

从「已有设备」打开气缸的「驱动接口」，展开手动／自动、使能、手动请求、复位、伸出超时和缩回超时。伸出与缩回动作仍复用同一个 CM 实例。气缸输出包括到位、当前请求完成、忙碌、状态、报警 ID 和请求受阻。

驱动优先按模式选择命令源，伸出和缩回输出互斥。生成工程的 `DB_U1_AF_Control` 暴露手动许可和各气缸的模式、请求。手动运行要求项目空闲、手动许可有效、工位许可与已配置的工位互锁有效。进入手动后，需要先收到空闲请求再接受伸出或缩回。

| 报警 ID | 含义 |
|---|---|
| 1001 | 伸出超时 |
| 1002 | 缩回超时 |
| 1003 | 自动伸出和缩回请求冲突 |
| 1004 | 伸出和缩回限位反馈同时有效 |
| 1005 | 模式或手动请求超出支持的取值 |

气缸的分方向参数可在节点检查器设置。工艺动作仍可设置等待上限和异常去向。AF 源码清单记录所用驱动接口版本。现有其它设备继续使用各自的目录驱动和反馈定义。

## 检查时序与生成 AF

1. 用「工位时序」运行正常反馈、反馈超时、启动许可未满足、运行中联锁失效等离线场景。场景会提供模拟反馈，并标出拦截动作的许可。「项目时序」用于验证工位间的调度。
2. 在「AF 生成」点击「生成 SCL 预览」。工程检查包括 CPU、模块、I/O 绑定、待关联反馈及连线。SCL 预览可以沿源码映射定位回画布。同一设备类型生成一份驱动 FB，工位中的各设备分别实例化。
3. 填写确认人并「确认此修订」。下载的 AF 源码 ZIP 包含 SCL、清单、源码映射和 AF 画布。源码包绑定已确认的修订，可用于后续导入。
4. 需要原生归档时，在硬件组态填写 CPU 完整目录标识，确认当前修订后选择「V19 编译并归档」。任务在独立 TIA 工程中执行。状态达到 `NATIVE_ARCHIVED` 并通过重新打开验证后，工作台会提供 `.zap19` 下载。

## 接口与验收

| 操作 | V2 接口 |
|---|---|
| 获取设备规格、动作与完成反馈 | `GET /api/v2/station-catalog` |
| 生成自然语言提案 | `POST /api/v2/projects/{project_id}/intent`，可传 `context_slice.station_id` 和 `context_slice.node_id` |
| 应用草稿修改 | `POST /api/v2/projects/{project_id}/patches`，使用 `set_station_design` 和当前 `base_revision` |
| 运行工位或项目离线时序 | `POST /api/v2/projects/{project_id}/simulate`，工位级传入 `station_id` |
| 检查并导入 AF 画布 | `POST /api/v2/station-import`，检查后通过 `confirm=true` 创建项目 |
| 下载已确认修订的 AF 源码 | `GET /api/v2/projects/{project_id}/source-package`，使用已批准的 `changeset_id` |
| 为当前已确认修订创建 V19 任务 | `POST /api/v2/projects/{project_id}/station-deliveries` |

桌面与移动端浏览器已验证设备添加、自然语言预览、手动绑定反馈、步骤修改与同步。夹爪、伺服和光电传感器的验收工程通过 TIA V19 编译（0 个错误、14 个警告），并验证了 `.zap19` 的重新打开和下载。该验收覆盖工程生成与归档，现场设备仍需联调。

类型端口样例验证了气缸到位信号、公开端口、工件号传递和接收确认。浏览器已实测类型不匹配拦截、兼容端口拉线、端口编辑和交接超时。该样例的 TIA V19 归档编译为 0 个错误、26 个警告，重新打开和下载哈希核对通过。
