### 1.1 环境噪声（重要，非测试失败）

首次执行 #1 / #5 / #7 时输出尾部出现：

```
[100%][safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]
{"count":116,"threshold":50,"scope":"turn",
 "targets":["...\\Temp\\pytest-of-vboxuser\\garbage-..."],"targetCount":1}
```

这是 WorkBuddy 的批量删除保护钩子拦截了 pytest 清理历史临时目录（116 > 阈值 50），使 pytest 在 teardown 阶段返回 1 且不打印汇总行。**测试本身全部通过**。加 `--basetemp=<独立目录>` 后得到干净的 `162 passed / exit=0` 与 `3 failed, 73 passed`。
→ 路由 **NoOne**（环境问题），但建议 CI 固定 `--basetemp`，否则「全绿」结论在他人机器上不可复现。

**退出码读取口径（避免误读）**：所有命令均以 `{ ...; <命令> 2>&1; echo "XXX_EXIT=$?"; } | tee <证据文件>` 包装，后台任务管理器回报的整体 shell 退出码恒为 0（因末尾 `echo` 成功），**不代表被测命令的退出码**。本报告及证据文件采用的是写入文件内的 `PYTEST_EXIT` / `PYTEST_FULL_EXIT` / `VITEST_EXIT` / `DOTNET_TEST_EXIT` / `NAMED_EXIT` / `HANG_EXIT` / `PROBE_EXIT` / `QA_PYTEST_EXIT` / `ENGINEER_EXIT` 等真实值；例如 `01_pytest_v2_targeted.txt` 内为 `PYTEST_EXIT=1`（钩子噪声），`01b` 内为 `PYTEST_EXIT=0`，`09` 内为 `QA_PYTEST_EXIT=1`（6 项源码缺陷）。二者不可混用。
