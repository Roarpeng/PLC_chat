# PLC_chat 工艺工作台设计方向

PLC_chat 帮工程师把设备及工艺描述变成可编辑、可验证、可交付的 AF 工程。工程师负责确认工艺意图、接口和验收条件。系统负责生成一致的工位模型、驱动实例、PLC 变量和 TIA 工程。

## 一条主流程

| 用户操作 | 系统输出 |
| --- | --- |
| 描述工艺 | 工位图、设备清单、主流程、异常路径以及影响行为的待确认项 |
| 确认和修改 | 全局调度图与可下钻的工位图，共用模板的修改影响预览 |
| 验证工况 | 可重复运行的正常和异常用例，失败条件对应工步及信号 |
| 导出博途 | 从确认过的修订生成命名变量、AF 文件夹和代码，记录 TIA 编译、归档及还原结果 |

全局画布聚焦工位、调度和交接。站内默认聚焦当前工步，按需查看详细设备、信号线和参数。对话、画布和表格应能交替使用。

## 一份工程模型

采用 V2 的服务端 EngineeringIR 保存工程语义，将 V5 的站内时序、工位下钻、点表绑定和导出交互并入同一工作台。对话、画布和表格都提交结构化修改。执行转移、信号连接和互锁分别建模，统一通过校验、差异预览和修订记录。SCL、标签表、TIA 文件夹和诊断定位由确定性编译生成。

AF Basic 文件夹版保留三个职责层。Unit 负责调度与交接，EM 管理工位动作与等待，CM 提供可复用、版本化的设备驱动。A/B/C 工位共用工位模板，各自实例化设备和 I/O。修改共用模板时先展示受影响的工位及变更。软件许可和设备反馈通过接口表达，现场信号含义、地址和安全条件由工程师确认。

AI 负责将描述映射为可审查的工位、设备、动作和条件，建议复用已验证模板，并提出与工艺匹配的验收场景。工程版本、人工确认、编译证据和离线模拟结果均可追溯。

## 以 KUKA 工程验收

当前 V5 离线交付已验证命名 I/O、原生 AF 分组和 V19 归档链。现有导出仍要求固定 KUKA 工位布局，无法编译已配置的 ST60 整线调度。它可用于回归验证文档中的交付行为。

下一阶段先复现同一工艺，包括取放工具、定时作业、附件更换与续作，再验证一个布局变体。复制第四个工具休息位、单独分配 I/O、修改一条共用规则后，工程师可在同一工作台查看修改范围、重跑场景并生成原生归档。验收要求移除导出对固定工位编号的依赖，编译结果与本次确认的工程修订对应。

优先验证工具两端在位、机器人退出后才锁紧、无可用附件时等待，以及作业对象缺失时撤销许可并报警。换附件期间的计时策略和 KUKA 握手含义作为显式工艺参数评审。
